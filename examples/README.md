## Bundled synthetic screenshots

`baseline.png` and `candidate.png` are synthetic bilingual dashboard screenshots generated by
`scripts/generate_demo_assets.py`. The candidate includes a card-shadow adjustment, a missing
refresh glyph, and a clipped Chinese primary-action label.

```bash
renderwitness demo --output reports/demo
```

The demo uses a metric-only heuristic. It identifies pixel changes; it does not establish the
semantic diagnoses above. The fixtures contain known changes so humans can inspect them and the
software pipeline can be tested without model access.

To regenerate the screenshot files after deliberately changing their renderer:

```bash
python scripts/generate_demo_assets.py
```

## Runnable screenshot suite

```bash
renderwitness suite examples/suite.json --output reports/example-suite
```

Use a new or empty output directory. The suite deliberately exercises different CI outcomes:

| Scenario | Expected status | Reason |
|---|---|---|
| `unchanged-control` | `passed` | Baseline is compared with itself |
| `bilingual-regression` | `failed` | Seeded changes exceed a zero changed-pixel budget |
| `review-only` | `passed` | The same changed image is reviewed with the inherited budget disabled |

**Expected process exit: 1.** A failing regression gate here demonstrates the fixture working.
Open `reports/example-suite/index.html` and inspect its case reports, `summary.json`,
`summary.md`, and `junit.xml`.

## Real browser capture example

Install the optional browser tools once:

```bash
python -m pip install -e '.[capture]'
python -m playwright install chromium
```

Run the complete browser example:

```bash
python scripts/run_browser_demo.py --output reports/browser-demo
```

The script opens local pages from `examples/web/`, masks their dynamic clock, captures desktop
(1440 × 900) and mobile (390 × 844) baseline/candidate pairs, and runs a zero-budget suite.
Two seeded regression cases should fail and an unchanged control should pass.
The script returns 0 after verifying those expected outcomes; a directly executed regression
suite returns 1 for its intentional gate failures.

The output includes screenshots and capture sidecars in `reports/browser-demo/images/`,
the generated `suite.json`, and the review bundle at `reports/browser-demo/review/index.html`.
Choose a new output directory for another run.

The browser fixture contains intentional label clipping, an icon disappearing, and a mobile
layout overflow. It uses fixed data and local assets apart from an explicitly masked clock.
See the [fixture guide](web/README.md) for the seeded changes and the Python capture example,
and [capture documentation](../docs/capture.md) for provenance and real-browser tests.

The unchanged suite control compares one saved screenshot with itself. The optional browser
test separately recaptures the same masked page twice and checks that their hashes match.

## Design sketches and benchmark labels

- `suite.json` is the executable version-1 JSON suite format.
- `scenarios.yaml` is an earlier design sketch for container orchestration and capture assertions.
  The CLI does **not** execute it.
- [Benchmark labels](../benchmarks/README.md) describe the synthetic screenshot pair. They do not
  constitute a multi-model evaluation or a measured semantic-accuracy claim.

Contributed fixtures should be synthetic, permissively licensed, or owned by their contributor.
Do not add private product or customer screenshots.
